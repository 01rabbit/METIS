# Scored investigation operations

The owner controls the platform and receives all worker results. Independent offline analysis
uses the pool; browser I/O and submissions share one exclusive resource. Read the current rules,
question format and remaining attempts from the authorized session before planning work.

Snapshot question text, artifact hashes, instance identity, expiry and response format into the
private case. Workers receive the exact question, evidence refs and expected format, not unrelated
answers. Confirm download integrity and archive completeness before claiming an absence.

Inventory the full package supplied within the authorized scope before narrowing analysis to
an evidence subdirectory. Read its briefs and manifests, including supporting instructions
outside that subdirectory. List required answers, reports and attachments with their source
document/section, due point and submission route in the private case. A dashboard may not
list every deliverable. Mark absent or conflicting instructions unresolved for the owner;
this check does not authorize access beyond the supplied package or assigned scope.

Track attempted answer bytes, evidence, rationale, time, response and remaining budget privately.
A rejected candidate is not a new source of truth. A transport error does not establish whether
submission occurred: reconcile with the platform before retrying. Never run parallel submissions
or spend another worker's budget. Answers may be instance-specific; bind them to the evidence
and instance that produced them. Do not synthesize missing answers from public solution keys.

Submission is a write. Use the user's authorization or an exact owner grant. Otherwise prepare
a candidate with evidence and request the owner action. Do not require repeated permission for
an existing valid grant. Prioritize questions by confidence, value and expected remaining cost.
Report unsolved and inconclusive items explicitly. The owner stays the main operator throughout.

Before a submission, bind the question's stable identity, current instance and answer bytes
to the visible writable control. Accepted or locked questions can disappear from the editable
list, so an input's current position is not a stable question number. After navigation or a
reconnect, verify both page identity and settled content; a changed URL alone can coexist
with stale application content. Ambiguous or multiple matching controls require observation
and reconciliation, not a guessed click. A prior accepted sibling cannot certify another
answer's meaning or evidence.

For acquisition, candidate evidence and retry reconciliation use [evidence locators](../soc-triage/references/evidence-locators.md). Preserve instance/question IDs, artifact digest, candidate reference and observed response per attempt; never substitute a current UI position for identity.
