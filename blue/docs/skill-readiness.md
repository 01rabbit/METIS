## 実測と判定

今回の具体性補強より前に凍結した技能本文を使うv1の独立16ケース・36判定項目は、LAN内OllamaとClaude Desktopの
UI表示Opus 4.6・Mediumで全通過しました。同条件のUI表示Opus 4.8は説明文を加え、
JSON形式に違反しました。禁止されていたツールも試行し、Desktop側でブロックされました。
形式不合格を知識36項目の誤答とは解釈せず、指示への追従失敗として記録しています。

採点基準を変えず末尾の出力契約を加えたv2では、既存16ケースと新規8ケースを使います。
OllamaのQwen 27B Q4は24ケース・60項目すべて通過し、別担当の再採点でも一致しました。
1回でinput 21,536 / output 1,006トークンです。Desktop v2も4.6・4.8（UI表示、Medium）が
各24ケース・60項目を通過し、両方とも可視ツール試行0でした。各モデル1回の評価です。
Desktopの使用トークン数・バックエンドモデルIDは取得できず、推定値で埋めていません。

正解は採点側だけが持ち、確定したプロンプト・参照hashを私有記録に保持しています。
v2は問題と参照も増えるため、末尾文だけの改善効果を証明する比較ではありません。
古い9項目の簡易評価とも別プロトコルです。実測条件は[評価仕様](benchmark.md)へ記載しました。

現行コードの統合テスト180件が成功しました。接続実通信9項目とSplunk実製品3ケースは過去の成功記録です。
小規模の合成評価で、モデル世代全般の能力保証は行いません。

これらの旧評価結果は、改訂後の参照本文を検証したものとして転用しません。今回追加した
24ケース・55項目の所在・フィールド評価は[評価仕様](benchmark.md#technical-locator-regression)に
分けて記録しています。Ollama初回・補強後とも54/55項目で、時刻の起点とイベント年を取り違えました。
新評価は未合格のまま保持し、改訂版Opus 4.6/4.8も未再測定です。資料の所在・fieldが揃ったことを
モデルによる正しい適用の保証にはしません。監督付きの調査で、実環境のschemaと取得範囲を確認して利用することが前提です。
自律Tier 3能力、元資料全記述の意味的等価性、実環境の検知精度は別の評価対象です。

起点年の誤答が再発しています。正解や採点器を変えて成功扱いにはせず、未合格を保持します。

実組織への導入時には、保有する証拠形式、SIEMの権限・schema、ツールとsymbolsを確認し、

委ね、パーサー失敗を陰性とせず報告します。モデル評価の追加結果は[評価仕様](benchmark.md)に記録します。
