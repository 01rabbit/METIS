# ナレッジ移行の再監査

初期移行のファイル対応だけでは不十分だったため、元知識の主題、表現、実行機能を分けて
再監査しました。現行は21技能・38参照・検知61・対応手順12・索引2の134知識ファイルです。
[技能の判定](skill-readiness.md)と[表現レビュー台帳](expression-review.json)を併せて確認してください。

確認日: 2026-09-29。対象はMETISの作業ファイルとGit全オブジェクト・メタデータです。
元リポジトリは読み取り専用で照合し、変更していません。

## 発見と修正

初回移行には、提供元の資格略称、講座番号、演習番号、解答断片、固有IOC、旧検証結果が
残っていました。名称の置換だけでは十分でなかったため、これらを除去しました。
ネットワーク・演習回答のハンドブックと検体固有ルールは、防御的な証拠評価と汎用の
検知候補に再構成しています。検知・対応手順のファイル名もトピック名に変更しました。
旧番号を使った参照は実在する資料または検知カタログへ修正しました。

記載された過去の成功率はMETISの検証結果ではありません。検知候補の各分岐・クエリー方言・
センサーが未検証であることを明示しました。侵入実行、制御機器への操作、解答カタログは
引き継がず、分析・観測点・緩和策として必要な内容を残しています。

## 再検査

通常は次を実行します。資料を変更した場合、レビュー後に移行台帳の対象ハッシュも更新します。
ハッシュ不一致を無視してチェックを通さないでください。

```bash
python3 scripts/check_repo.py
python3 blue/scripts/audit_knowledge.py --source /path/to/source-checkout --history
.venv/bin/pytest tests/blue
```

提供元の識別語はリポジトリ内に保存せず、必要時に環境変数METIS_DENY_PATTERNで正規表現を
渡します。指定しない検査は、提供元識別語の不在を保証しません。履歴検査は到達不能な
Gitオブジェクトとreflog等のメタデータも対象にします。変更検出・移行漏れ・パス逸脱・
到達不能blob・Gitメタデータを含む7件の監査テストを追加しました。

これは完全な秘密情報検出器ではありません。匿名化や新たな符号化・画像内の文字は
意味のレビューも必要です。今回、解答を含むバイト列の例も本文の再構成で除去しました。
