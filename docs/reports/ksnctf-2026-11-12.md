# ksnctf progress and reusable techniques

Date: 2026-11-12

This report records only official-verifier outcomes and abstract techniques. It
does not contain flags, credentials, raw private data, or unverified candidates.

## Verified progress

Seven of 41 challenges have an observed official `result: true` verdict.

| Problem | Technique retained |

Each result above was counted only after the ksnctf official JSON endpoint
returned the boolean value `true`. Local extraction, recognizable text, HTTP
status, and static success-dialog text were not treated as solves.

## Throughput findings

The first portfolio pass was slower than necessary for four concrete reasons:

1. The same problem was sometimes registered once for its statement and again
   for its distributions. This split run identity and caused incorrect handoffs.
2. Heterogeneous challenges were bundled into one lower-tier assignment. A
   stalled obfuscation path then delayed unrelated mechanical work.
3. Evidence-backed candidates waited for other branches instead of being sent
   immediately to the official verifier.
4. An `unknown` ksnctf transport result blocked recovery of the same candidate,
   and terminal input could append a newline to an otherwise exact candidate.

The workflow now uses one canonical run per problem, groups parallel work by
analysis type, escalates ambiguous branches after one bounded attempt, and sends
each supported candidate as soon as it is ready. Official submissions remain
centralized in Daybreak to prevent races.

## Controller changes in this branch

- Recognize official ksnctf problem URLs and submit to the same-origin JSON API.
- Require HTTP 200, JSON content, and a strict boolean verdict.
- Refuse submission redirects and preserve existing attempt/rate limits.
- Permit a bounded retry of the same ksnctf candidate after an `unknown`
  transport or verdict result.
- Remove one terminal LF or CRLF from CLI stdin to avoid accidental line-ending
  submissions while preserving all other bytes.
- Document the canonical-run, homogeneous-parallel-queue workflow for a set of
  challenges.

## Validation

The focused CLI and web workflow suite covers strict JSON verdict parsing,
redirect refusal, duplicate prevention, rate limits, bounded unknown-result
retry, solved-state transitions, candidate redaction, and terminal line-ending
handling. Lint and static type checks also pass locally.
