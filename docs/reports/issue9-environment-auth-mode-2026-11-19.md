# Issue #9: optional environment-only web authentication

Set `METIS_WEB_AUTH_STORAGE=environment` in the METIS process to stop reading or writing `web_credentials` and to stop persisting platform authentication cookies in `web_runs.state`. Pass a credential variable name with `metis web open --token-env NAME` or `--cookie-env NAME`, or the corresponding catalog options. The variable's value must be provided through the process environment; it is not recorded in run configuration. An unknown storage-mode value fails closed.

The default remains `local` for compatibility with existing runs. The setting is per process, so it must be supplied to every METIS process; a process without it can still use legacy SQLite credentials. Switching to `environment` does **not** delete legacy SQLite rows, WAL/history, or backups. Existing local credentials can be removed explicitly with `metis web forget URL`, or with the separately proposed preview-first bulk operation. Operators should confirm that environment variables are supplied by an appropriate secret manager and rotate or revoke provider credentials independently. Environment variables can still be exposed to other processes with sufficient host privilege, so this is not an encrypted-at-rest credential vault.

Platform authentication cookies are discarded from newly saved run state in environment mode. This means a platform login session that depends on a changing Set-Cookie value may not survive across commands. A client created before a mode switch is fenced on its next platform request, and a later save cannot reintroduce its platform cookies. Challenge-origin cookies remain subject to the existing run-state policy. In-flight requests may already have sent authentication. Existing run rows that are never opened again retain their old cookies until separately forgotten.

Verification uses synthetic credentials only: legacy-row bypass, no platform-cookie persistence, explicit environment-variable authentication, stale-client fencing, mode restoration, and invalid-setting rejection. No real credential migration, Keychain access, or provider revocation was attempted. Issue #9 remains open.
