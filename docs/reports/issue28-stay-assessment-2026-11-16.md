# Issue #28: Stay attack feasibility assessment

The primary source is Michael Stay, [A Differential Meet-in-the-Middle Attack on the Zip cipher](https://eprint.iacr.org/2020/983.pdf) (ePrint 2020/983). Direct access to the PDF returned HTTP 403 on 2026-11-16. Search indexing exposed portions of the introduction, but not a reliably complete paper; therefore this assessment is not a full algorithm review.

The indexed introduction describes recovering a `rand` state from a timestamp and leaked header bytes, then a differential meet-in-the-middle technique for early key candidates and lattice reduction for the truncated LCG state. It reports a two-member recovery with GPU computation. This is distinct from the 2001 five-member ~2^39 estimate already cited in the original report; the estimate must not be transferred to the 2020 attack. A recovered PRNG seed alone is not the ZipCrypto key.

The current sandbox container is limited to one CPU, 512 MiB, and a request timeout of at most 300 seconds. Native compilation alone does not establish that either full attack will finish within those bounds. A safe implementation would need a verified complete algorithm and independently generated synthetic vectors; a bounded, cancellable worker with explicit candidate, memory and time limits; isolation with no network or host mounts; and end-to-end key validation against encrypted members and CRCs. Timeout or exhausted bounds must be inconclusive, never a claimed recovery. The present sandbox API and cost constraints require a separate design and measured feasibility work before advertising such an operation. No Stay key recovery was added without those prerequisites.

The new synthetic specialist-intent test exercises known-plaintext key recovery, decrypt-as-derived-artifact, and XOR. Its reduction stage is deliberately restricted to a true candidate plus a decoy; it exercises the actual attack worker but does not demonstrate the exhaustive search or Stay attack. The existing optional slow test covers exhaustive Biham–Kocher search separately.
